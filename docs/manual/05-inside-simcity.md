# V. Inside SimCity — 模擬器怎麼運作，以及怎麼用它

官方英文手冊第 41–45 頁。OCR 全文第 2414–2698 行。
章節原標題 `INSIDE SimCity — HOW THE SIMULATOR WORKS AND STRATEGIES FOR USING IT`。

這一章是手冊裡唯一講機制的部分，所以它是 `CLAUDE.md` §1.1 第 6 順位那個
「規則輔助 oracle」的本體。**每一節後面都附一段「對照原始碼」**——
規格層以 Micropolis 為準（第 1 順位），手冊只用來佐證或指出分歧。

> 導言：影響城市興衰的因素很多，分成內部（城市自身的結構與效率）
> 與外部（區域經濟、災難等）兩類。

## 分區（Zones）

城市分成三種主要分區：住宅、商業、工業。它們象徵城市賴以存在的三根柱子
——人口、工業、商業，三者缺一不可。

- **住宅區**是市民（Sims）居住的地方。他們在這裡蓋房子、公寓，以及教堂、
  學校這類社區設施。市民是商業區與工業區的勞動力。
- **工業區**放倉庫、工廠，以及其他不好看又會汙染、對周邊分區有負面影響的
  建物。都市規劃的主要目標之一就是把這些「嫌惡設施」和人住的地方分開。
  在這個模擬裡，工業區代表城市的**基礎生產**：這裡做出來的東西賣到城外的
  「外部市場」，把錢帶進城裡供未來成長使用。
- **商業區**代表城裡的零售與服務業，包括加油站、雜貨店、銀行、辦公室。
  商業區主要生產城市**內部**需要的商品與服務，這叫**非基礎生產**，
  或說為「內部市場」而生產。

### 對照原始碼

三種分區的圖塊編號與成長規則見
[`../re/07-traffic-and-zones.md`](../re/07-traffic-and-zones.md)。
手冊這一節是敘述性的，沒有可對的數字。

## 人口 — 住宅

控制住宅人口的主要因素是**出生率、工作與住宅的供給、失業率，以及城市的生活品質**。

- **出生率**在這裡其實是出生率（＋）與死亡率（−）的合計。SimCity 裡出生率永遠為正。
- **工作供給**（就業率）是「目前的商業與工業人口」對「住宅總人口」的比值。
  概略的原則是：**商業區與工業區的數量加起來，應該大致等於住宅區的數量。**
  城裡的工作比居民多，新移民就會被吸引進來；區域性衰退讓工作市場萎縮時，
  人會為了找工作而遷出。
- **住宅**蓋在住宅區裡。這些分區必須**有電**，而且**用道路連到工作地點**。
  住宅區裡蓋出什麼樣的建物，受地價與人口密度影響。
- **生活品質**是指派給不同分區位置的相對「吸引力」。它被負面因素（汙染、犯罪）
  與正面因素（公園、可及性）左右。

### 對照原始碼

**就業率那條對得上，而且是逐字對得上。** `SetValves`（`s_sim.c:414`，
本專案 [`internal/sim/census.go`](../../internal/sim/census.go)）：

```
Employment = (ComHis[1] + IndHis[1]) / NormResPop        ← 手冊的「就業率」
Migration  = NormResPop × (Employment − 1)               ← 手冊的「工作比居民多就吸引移民」
Births     = NormResPop × 0.02                           ← 手冊的「出生率永遠為正」
```

`Employment` 大於 1（工作比人多）時 `Migration` 為正，小於 1 時為負。
「商業＋工業 ≈ 住宅」這條經驗法則就是 `Employment ≈ 1` 的白話版。

⚠ **手冊漏了一條硬規則。** 住宅需求還有一個**上限開關**，手冊完全沒提：
`ResPop > 500` 而城裡沒有體育場時，正的住宅需求會被直接歸零
（`ResCap`，見 [`../../internal/sim/message.go`](../../internal/sim/message.go)
與 [`../../internal/autoplay/demandcap.go`](../../internal/autoplay/demandcap.go)）。
工業要海港、商業要機場，同理。**照手冊蓋城市會撞到一堵手冊沒寫的牆。**
遊戲裡是用訊息提示的（「市民要求興建體育館」），不是寫在手冊裡。

## 外部市場 — 工業

影響城市的變數有上千個，全部都受玩家的行動影響——**只有一個例外**。

**外部市場**（城市之外的經濟情況）由模擬本身控制，玩家做什麼都改不了它。
從很多角度看，外部市場是一切城市成長的原始來源：城鎮常常是先成為生產中心
（鋼鐵城、煉油廠之類）來服務周邊區域的需求，隨著時間過去，外部市場會跟著
城市周邊的區域成長而擴大。

城裡的工業會試著跟著外部市場一起成長。要成長得成立兩件事：**有擴張的空間**
（更多工業區）與**足夠的勞動力供給**（更多住宅區）。

### 對照原始碼

**這一節與程式碼有分歧，要記下來。** 手冊說外部市場「隨時間成長」，
但本專案讀到的 `SetValves` 裡，外部市場是一個**只看難度、不隨時間變**的常數：

```
GameLevel 0（Easy）  → ExtMarket = 1.2
GameLevel 1（Medium）→ ExtMarket = 1.1
GameLevel 2（Hard）  → ExtMarket = 0.98
```

推論等級：**已確認**（讀到 `internal/sim/census.go` 的實作，出自 `s_sim.c:414`）。
所以手冊那句「as time passes, the external market grows」在 1.10 版的程式裡
**沒有對應的程式碼**——它描述的可能是設計意圖，或是別的版本。
遇到衝突以原始碼為準（`CLAUDE.md` §1.1）。

## 內部市場 — 商業

內部市場完全由城內的條件決定。商業區創造的內部生產，代表城裡買賣與消費的
一切：食品店、加油站、零售店、金融服務、醫療照護等，全都要靠附近有人口才做得下去。
在 SimCity 裡，**內部市場的大小決定商業區興旺的速率**。商業區需要足夠的
已劃分土地可蓋，也需要現成而充足的勞動力可雇。商業區蓋出什麼樣的建物，
主要受地價與人口密度影響。

商業區為了服務擴張中的內部市場而成長。人口少、需求小的時候商業成長通常很慢；
城市長大之後商業成長會加速，內部市場會變成城市總生產裡大得多的消費者。
**這個加速效應——內部／商業部門的成長超過外部／工業生產的那一刻——
可以在短短幾年內把一個五萬人的睡城變成二十萬人的繁華首府。**

### 對照原始碼

`SetValves` 的內部市場：

```
IntMarket   = (NormResPop + ComPop + IndPop) / 3.7
ProjectedComPop = IntMarket × LaborBase
```

`LaborBase = ResHis[1] / (ComHis[1] + IndHis[1])`，上限 1.3、下限 0——
這就是手冊說的「需要現成而充足的勞動力可雇」。除數 3.7 是原版的字面常數。

手冊那句「五萬變二十萬」是宣傳語氣，但機制方向對得上：`IntMarket`
把住宅、商業、工業人口**加總**再除，所以三者一起長的時候商業需求是**複利**的。

## 稅率

稅率控制城市的收入。稅金每年（模擬時間）收一次，收的時候會跳出**預算視窗**，
交代財政細節並讓玩家調整稅率。模擬依每個分區的**地價、目前的開發程度、
以及當前稅率**來核算應收金額。

稅率對城市的成長率有全域性的影響：

- 訂低（**0–4%**）成長會很快，但城市收入低。
- 訂高（**10–20%**）短期收得多，但長期稅收會隨人口一起下滑。

稅收要高到足以投資新的開發，又要低到不會把居民與商家嚇跑。
想實驗「成長控制」的話，高稅率是一種手段。

### 對照原始碼

稅率進 `SetValves` 的方式是一張**查表**：`z = CityTax + GameLevel`（上限 20），
三個需求各加上 `taxTable[z]`。所以稅率是**平移三條需求曲線**，不是乘上比例。

⚠ **手冊另一處講的是不同的數字。** 使用參考章（`Growing a City`）寫的是
`The optimum tax rate for fast growth is between 5 and 7%`——那是一個**區間**。
社群常見的「7% 是黃金稅率」把區間的上緣講成單一數字，手冊沒有這樣寫，
也沒有說預設值是 7%（`CLAUDE.md` §1.1 的三個例子之一）。

本專案自動玩家的實測（八個劇本 × 五顆種子）與手冊一致：
**4%–9% 之間差不多平，10% 以上急速崩壞**。見
[`../../internal/autoplay/player.go`](../../internal/autoplay/player.go) 的稅率註解。

## 預算

城市預算影響城市成長的方式。基礎建設成本由三個部門代表：**警察、消防、交通**。
三個部門的經費可以分別設定，每年各自提出一個請款額度，玩家可以全額或部分撥款，
在安全需求與財政之間取捨。

### 警察局

警察局降低轄區內的犯罪率。**警察局的有效半徑與警察部門的撥款額度相關。**

### 消防隊

消防隊預防與撲滅火災。**撥款額度決定消防隊的有效半徑**：半徑內的火災會比
半徑外撲滅得快得多，而且一開始起火的機率也比較低。
**消防隊每座每年的經費是 $100。**

### 交通部門

蓋道路與鐵路要付建造費，之後每年還要付維修費。交通網愈大，養護愈貴。
不付或付不出維修費的話，道路會慢慢劣化到不能用。每一格的維修費是：

| 項目 | 手冊 | 本專案（照 Micropolis）|
|---|---:|---:|
| 道路 Road | $1 | 1 |
| 橋 Bridge | $4 | **5** |
| 鐵路 Rail | $4 | **2** |
| 鐵路隧道 Rail tunnel | $10 | **沒有這個項目** |

### 對照原始碼

- **消防隊 $100 對得上**：`FireFund = FireStPop × 100`
  （[`internal/sim/census.go`](../../internal/sim/census.go)）。已確認。
- **維修費四項有三項對不上**（上表）。這一項**沒有 DOS 資料檔可以裁判**
  ——維修費不寫在 `.PTF` 裡。規則層照 Micropolis，衝突記在
  [`../../CONTEXT.md`](../../CONTEXT.md) §5.5。
  軟體世界說明書 p.63 的數字與英文手冊一致（道路 $1、橋 $4、鐵路 $4、隧道 $10），
  所以兩本手冊是同一個來源，而程式是另一回事。

## 電力

電力讓現代城市成為可能。把電有效而可靠地送到每一個分區，就是「電力管理」的目標。

模擬會定期檢查整張電網的連通性。**一個分區只要（透過其他分區或電線）連到
發電廠，就算有電。**

**分區必須有電才會發展。** 火災、龍捲風、地震、推土機都可能打斷電線，
造成局部停電。沒電的分區會停止發展，而且電力若沒有很快恢復，
**分區會退回原本的空地狀態**。

多蓋幾座發電廠、多拉幾條線可以讓電網更可靠，但拉線要花建造費。

### 對照原始碼

「分區也導電」對得上：分區圖塊帶 `CONDBIT`，所以電可以穿過相鄰的分區傳遞
（[`../re/05-power-scan.md`](../re/05-power-scan.md)）。

⚠ **手冊沒講的一件事，而它會改變玩法**：`DoPowerScan` 在導電格數超過發電量上限
（燃煤 700 格、核能 2000 格）時**整批放棄**，不是「按比例供電」。
所以停電是**跳階發生**的：容量剛好夠的時候一切正常，多一格就有一大片同時變暗。
見 [`../re/05-power-scan.md`](../re/05-power-scan.md)。

## 交通 — 車流

交通網是城市結構裡最重要的元素之一，它在城裡運送市民與貨物。
都市地區的道路通常佔掉 25%–40% 的土地。路上的車流顯示路網的哪些路段用得最兇。

車流的模擬用的是一個叫**「行程產生」（Trip Generation）**的程序。每一個有人口的
分區會隨時間產生若干趟行程，數量看人口。每一趟從起點分區出發，沿著道路走，
**走到「適當的終點」就在終點分區結束，否則這趟行程失敗**。
行程失敗代表某個分區的可及性不足，而那會限制它的成長。

大部分行程代表市民通勤上下班，另外還有購物、休閒等產生的車流。
分析車流時，模擬器測試下列路線：

| 起點 | 終點（手冊）|
|---|---|
| 住宅區 | 商業區與工業區 |
| 商業區 | 住宅區與工業區 |
| 工業區 | 住宅區 |

市民從起點開出去時有一個有限的**「行程範圍」**可以找終點。
**車流大會縮短行程範圍。** 終點太遠這趟就不成功，而**反覆不成功會讓市民搬離起點分區**。

每一條路的容量有限，超過就形成塞車。塞車會大幅降低道路容量，讓問題惡化。
車流狀況變動很快，避免交通問題的辦法是**提供好幾條替代路線**。

**道路必須與分區相鄰，該分區才算接上車流網。分區不像導電那樣導車流。**

### 對照原始碼

行程範圍、周長 12 個出發點與失敗計數見
[`../re/07-traffic-and-zones.md`](../re/07-traffic-and-zones.md)。

⚠ **終點表比手冊寬。** `s_traf.c:274` 的 `targLow`／`targHigh`
（[`internal/sim/traffic.go`](../../internal/sim/traffic.go)）：

| 起點 | 圖塊範圍 | 實際涵蓋 |
|---|---|---|
| 住宅 | `COMBASE … NUCLEAR` | 商業、工業，**外加警局、消防隊、體育場、港口、機場、發電廠** |
| 商業 | `LHTHR … PORT` | 住宅、商業、工業、港口 |
| 工業 | `LHTHR … COMBASE` | 住宅 |

手冊只列了「商業與工業」「住宅與工業」「住宅」，而程式的範圍是連續的圖塊區間，
把中間的特殊建物一起算進去了。**工業那一列兩邊一致**，另外兩列手冊講得比程式窄。

## 汙染

城市的每一個地方都在追蹤汙染值。這是一個綜合的「嫌惡程度」，
包含空氣與水汙染、噪音汙染、有毒廢棄物等。**汙染對住宅區的成長有負面影響。**

汙染的主要來源是工業區，而**工業區製造的汙染隨它的成長程度增加**。
車流是另一個來源。對抗汙染的手段有限：降低車流密度、限制工業開發、
把汙染源和住宅區分開，都有幫助。

### 對照原始碼

汙染權重表見 [`../re/06-scans.md`](../re/06-scans.md)。

⚠ **DOS 1.10 的汙染權重比 Micropolis 低**（六個權重全部是 Micropolis 註解裡的舊值），
已從執行檔讀到位元組定案，見 [`../re/18-dos-parity.md`](../re/18-dos-parity.md) §6.3。
**remake 照 Micropolis**，不往 1991 年調。所以拿手冊的定性描述對這一層時，
要記得數值在兩個版本之間動過。

## 犯罪

犯罪率受**人口密度、當地執法、地價**影響。某地區的人口密度上升，犯罪數就上升；
**地價低的地區犯罪也會上升。**

處理高犯罪率最有效的方法是在該區設警察局——依撥款程度，警察局會降低
其影響範圍內的犯罪率。長期的做法則是**提高該區的地價**，其中一個手段是
拆掉重劃（都市更新）。

### 對照原始碼

`CrimeScan`（`s_scan.c:300`，見 [`../re/06-scans.md`](../re/06-scans.md)）：

```
z = 128 − LandValueMem[x][y]     ← 地價愈低犯罪愈高
z += PopDensity[x][y]            ← 人口密度
夾限 300
z -= PoliceMap[x>>2][y>>2]       ← 警力涵蓋
夾限 0…250
```

**三個因素與手冊完全一致**，而且順序也一樣。地價為 0（沒有人造物）的格子
犯罪直接設 0。這是全章對得最乾淨的一節。

## 地價

地價是都市結構最根本的面向之一，一個地區的地價影響它被怎麼使用。
在這個模擬裡，地價根據**地形、可及性、汙染、以及到市中心的距離**計算。

居民上班要走的路愈遠，他們住的地方地價愈低（部分是因為交通成本）。
商業區的價值則很依賴民眾的可及性。

地價也受周遭地形影響：**靠近水域、樹木、農地或公園，地價會上升。**
把分區巧妙地放進地形裡、少推平一點，就能利用這個天然優勢。

### 對照原始碼

`PTLScan`（`s_scan.c:200`，見 [`../re/06-scans.md`](../re/06-scans.md) §三）：

```
dis  = 34 − 到城市重心的曼哈頓距離（上限 32）
dis <<= 2
dis += TerrainMem[x>>1][y>>1]      ← 地形（水與樹加分）
dis -= PollutionMem[x][y]          ← 汙染
if CrimeMem[x][y] > 190: dis -= 20 ← 犯罪
夾限到 1…250
```

**手冊列的四項與程式的四項不是同一組**：

| 手冊 | 程式 |
|---|---|
| 地形 terrain | ✓ `TerrainMem` |
| 汙染 pollution | ✓ `PollutionMem` |
| 到市中心的距離 | ✓ 到 `CCx/CCy` 的曼哈頓距離 |
| **可及性 accessibility** | **沒有獨立項** |
| — | **犯罪**（> 190 時扣 20），手冊這一節沒列 |

「可及性」在程式裡是以另一種形式存在的：**只有格子裡有 `>= ROADBASE` 的
人造物才算地價**，沒有人造物的格子地價是 0 且不計入平均。
所以它是一個開關，不是一個加權項。

⚠ 手冊說的「農地」在初代裡沒有對應的圖塊——一代沒有農業分區。
這句應該是泛指未開發的綠地（`TREEBASE … WOODS`）。

## 這一章當 oracle 的可信度

逐節核對下來，手冊在**定性方向**上幾乎全對，但有三種系統性的偏差，
引用前要知道：

| 偏差 | 例 |
|---|---|
| **漏掉硬規則** | 體育場／海港／機場的需求封頂完全沒寫；發電量超限是整批放棄不是按比例 |
| **描述比程式窄** | 行程終點表少列了特殊建物 |
| **列的項目與程式的項目不同組** | 地價：手冊有「可及性」而程式沒有獨立項，程式有犯罪而手冊沒列 |
| **描述的不是這一版** | 外部市場「隨時間成長」在 1.10 的程式裡沒有對應碼 |
| **數字對不上** | 道路維修費四項有三項與 Micropolis 不同 |

對得最乾淨的是**犯罪**（三個因素與順序都一致）與**消防隊每年 $100**。

所以它的正確用法是**佐證與命名**（機制叫什麼、方向是什麼），
不是**取值**。要數字就回 Micropolis 或 DOS 資料檔。
