# 發行 AppImage 對 DOS 原版的畫面與操作流程對拍（2026-09-01）

## 結論

`v.1.0.0-20260901` 的完整版 AppImage 與 DOS 1.10 原版在畫面與操作流程上對得起來，
文字不計。判準分兩層：**發行的 AppImage 與工作樹現建的執行檔畫出來的畫面無可分辨
差異**（十四幕，其中十三幕有逐位元完全相同的截圖），而 **remake 對 DOS 原版的四項
逐格與逐像素數字，用 AppImage 當 remake 側重新量過，與
[`visual-parity-2026-08-31.md`](visual-parity-2026-08-31.md) 一致**。

唯一與八月三十一日不同的數字是招牌那一幕，成因是三個開場按鈕已中文化；差異的
93.7% 落在按鈕框內，其餘是 DOS 側的滑鼠游標。

這一輪沒有發現 AppImage 專屬的缺陷。包裝層（發行旗標、內嵌字型與圖集、
AppImage runtime、資料路徑解析）沒有改變任何一幕的畫面。

| 項目 | 值 |
|---|---|
| 受測檔 | `dist-all/v.1.0.0-20260901/full/chengshi-v.1.0.0-20260901-full-local-linux-amd64.AppImage` |
| 受測檔 SHA-256 | `d888f73f2198f3385d3bc4a2d05a6ea6ff7bedcf322068718f0e33d7f849a6c7` |
| 原版 | DOS 1.10 `SIMCITY.EXE`，SHA-256 `66457cc456570b356bd44fa5c8617f27d3dffddd997e1591e97230f85a34189f` |
| 對照組 | 同一份工作樹用發行旗標 `-s -w -X main.version=v.1.0.0-20260901` 現建的 `chengshi` |
| 畫布 | 1920×1050（原版 640×350 的整數三倍），像素總數 2 016 000 |
| 劇本／風格 | 悲情城市 1（達斯維利）／WEST |

AppImage 內含的 `SIMCITY 1.10` 與 `workplace/dos110/SIMCITY 1.10` **逐位元相同**
（62 個檔案，逐檔雜湊再合併後為 `2eaaf1a1502467f1737d09f1ec087cb22c33b5576295a99f5db1fffe3c7b8d80`）。
所以任何像素差異都不會來自兩邊素材不同。

AppImage 裡的執行檔與現建的那顆 SHA-256 不同。Go 的輸出位元組會隨建置路徑與工具鏈
版本改變，發行包建於 2026-09-01 12:03、對照組建於同日稍晚且中間重建過建置 image，
所以雜湊不同不足以判定內容不同，改由畫面判定。

容器裡沒有 FUSE，AppImage 以官方的 `APPIMAGE_EXTRACT_AND_RUN=1` 模式啟動。
FUSE 掛載那條路徑不在本輪涵蓋範圍。

## 為什麼判準是成對重複量測

這個遊戲的畫面**不是逐次可重播的**，有兩個獨立成因，兩顆二進位都有：

1. **模擬在劇本簡介蓋著的時候照跑。** `updateTitle` 只擋招牌與劇本選單兩幕；
   進到遊戲之後 `Update` 每一畫格都呼叫 `world.Frame()`。`NewGame` 的
   `speedLevel` 是零值 0，但世界的 `SimSpeed` 來自劇本檔（`s_fileio.c:454` 設 3），
   所以按下 `0` 之前模擬一直在前進。AppImage 比現建版多花一兩秒解包，
   用固定秒數等待就會讓兩邊「拍照時已經跑了幾刻」不一樣。
2. **讀城市檔本身會擲亂數。** `game.LoadCity` 走
   `LoadCitySeed(path, sim.RandomSeed())`，而 `RandomSeed()` 是
   `time.Now().UnixNano()`（`internal/sim/rand.go:147`）；`DoSimInit` 的那次
   `MapScan` 用得到它。`-seed` 只接到「開新城市」那條路，`-load` 與 `-scenario`
   都沒有（`cmd/chengshi/main.go:165–186`）。**同一顆二進位讀同一份城市檔，
   兩次啟動的畫面就已經會差幾十到幾百個像素。**

第一點靠配方消掉：等視窗真的出現再動作，並讓兩側都讀同一份存成 `SimSpeed=0` 的
城市檔（`MiscHis[57] = 0`，實測 `SimFrame` 與 `MoveObjects` 都在 `SimSpeed == 0`
提早返回）。第二點消不掉，所以判準是：

> **乙側與甲側的最小差距，不大於任一側自己跟自己的最大差距。**

兩側各拍三張，於是每側有三個「自己跟自己」的樣本、九個跨側樣本。
沒有世界的畫面（招牌、劇本選單）雜訊底線是 0，判準自動收斂成逐像素相同。

驗證這個雜訊確實存在而非事後解釋：讀同一份暫停城市檔、等三秒再 `Ctrl-S` 存回，
**存回來的檔與輸入不同，而且三次互不相同**；同一個行程內間隔三秒的兩張截圖
則逐位元相同。所以變動發生在讀檔那一刻，不在執行期。

十四幕的操作流程都是**驅動 AppImage 自己走出來的**，不是用命令列參數跳進去：
招牌上點「選悲情城市」進劇本選單、點縮圖進遊戲、按住選單標題拉開四個下拉選單、
`Ctrl-G`／`Ctrl-B`／`Ctrl-U` 開三個資料視窗、`Ctrl-C` 關 City Form、
按住 `Q` 加左鍵叫出查詢面板。

## 階段 B：AppImage 對現跑的 DOS 原版

DOS 基準當日現跑（原版素材與原版畫面都不進版控），remake 側全部由 AppImage 產生。

| 比什麼 | 本輪（AppImage） | 2026-08-31（現建版） |
|---|---|---|
| 編輯視窗完整 512 格 | **502 格逐位元相同**，10 格為兩側不同的游標覆蓋 | 502／512 |
| City Form 完整區域 | 130 583／131 600（99.227%） | 130 581／131 600（99.226%） |
| City Form 地圖本體 | 107 836／108 300（99.572%） | 107 834／108 300（99.570%） |
| 劇本選單 | 223 867／224 000（99.941%） | 223 867／224 000（99.941%） |
| 招牌 | 221 602／224 000（98.929%） | 223 849／224 000（99.933%） |

招牌那一列的差異由兩塊構成：**2 247 個像素落在三個開場按鈕框內**
（`(95,183)-(309,213)`、`(319,183)-(533,213)`、`(209,223)-(423,253)`），
那是按鈕文字中文化的結果；框外剩 151 個像素，bbox `(175,321)-(190,335)` 為 16×15，
是 DOS 側的滑鼠游標。DOS 側的招牌基準與八月三十一日那次**逐位元相同**，
所以變的是 remake 側，而且是刻意的。

其餘九幕不重新量原版：階段 A 已證明 AppImage 與現建版在那些畫面上無可分辨差異，
現建版對原版的數字在 [`visual-parity-2026-08-31.md`](visual-parity-2026-08-31.md)。

## 重跑入口

```bash
tools/appimage_parity.sh v.1.0.0-20260901          # 兩階段全跑
STAGE=a tools/appimage_parity.sh v.1.0.0-20260901  # 只做同源證明
STAGE=a A_KIND=dev B_KIND=dev tools/appimage_parity.sh v.1.0.0-20260901  # 正對照
ONLY="cityform budget" STAGE=a tools/appimage_parity.sh v.1.0.0-20260901 # 只跑幾幕
```

`A_KIND` 與 `B_KIND` 設成相同就是正對照，量的是配方本身的雜訊。收據在
`workplace/appimage-parity/`（gitignore）：逐幕 JSON、每幕六張截圖、
起點城市檔、階段 A 全文記錄。

## 已知的刻意差異

- 三個開場按鈕已中文化，與原版英文不同。這是 §階段 B 招牌那一列的主要成分。
- 其餘語言、年份基準、防拷兩幕的省略與 remake 新增的三樣功能，
  見 [`visual-parity-2026-08-31.md`](visual-parity-2026-08-31.md) 的同名段落。

## 本輪未涵蓋

- **公開版 AppImage 沒測**，只測完整版。兩者的差別是有沒有內含原版素材與音樂。
- **FUSE 掛載路徑沒測**：容器裡以 `APPIMAGE_EXTRACT_AND_RUN=1` 啟動。
- **Windows 與 macOS 發行包沒測**，本輪只涵蓋 Linux AppImage。
- 災難與精靈、工具放置與存讀檔、六種圖形集切換這三組畫面不在本輪的十四幕內。
- 階段 B 只重新量四項；其餘九幕靠階段 A 繼承，不是當日對原版直接量到的。
