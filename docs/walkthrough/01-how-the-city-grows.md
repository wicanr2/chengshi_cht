# 城市怎麼長大

每一節後面標的是這條規則出自哪裡。`s_*.c` 是 Micropolis 的原始檔名，
本專案的對應實作在 `internal/sim/`。

## 一、成長迴圈：三種分區互相咬住

住宅、商業、工業不是三條獨立的進度條，它們由**三個需求閥**（`RValve`／
`CValve`／`IValve`）驅動，而三個閥每次普查重算一次：

```
住宅：Employment = (商業人口 + 工業人口) / (住宅人口 / 8)
      Migration  = (住宅人口/8) × (Employment − 1)
      → 工作比人多就有人搬進來，反過來就搬走

商業：IntMarket = (住宅人口/8 + 商業人口 + 工業人口) / 3.7
      → 商業需求看的是「城裡總共有多少人」，三者一起長才會複利

工業：ProjectedIndPop = 工業人口 × LaborBase × ExtMarket
      ExtMarket 只看難度：簡單 1.2、普通 1.1、困難 0.98（**不隨時間變**）
```

出處：`s_sim.c:414 SetValves`，本專案 `internal/sim/census.go`。

**能用的結論：**

- **商業區＋工業區的數量，大致等於住宅區的數量。** 這是 `Employment ≈ 1`
  的白話版，官方手冊也是這樣寫的。偏一邊就會有一種分區長不動。
- **三者一起長才會加速。** 商業需求的分母是總人口，所以前期慢、後期快。
- **困難難度的外部市場是 0.98（小於 1）**，工業會自己萎縮。這不是錯覺。

## 二、手冊沒寫的三堵牆

這是本專案在讀 `internal/sim/message.go` 時才發現的，**官方手冊完全沒提**，
而它會讓城市在某個大小突然停住：

| 條件 | 後果 |
|---|---|
| 住宅人口 > 500，城裡**沒有體育場** | 正的住宅需求被**直接歸零** |
| 工業人口 > 70，城裡**沒有海港** | 正的工業需求被直接歸零 |
| 商業人口 > 100，城裡**沒有機場** | 正的商業需求被直接歸零 |

出處：`internal/sim/message.go` 第 26／28／30 個訊息相位設 `ResCap`／`IndCap`／
`ComCap`，`SetValves` 的最後三行執行歸零。

**這三堵牆有多硬**：本專案的自動玩家先前沒蓋這三樣，結果給它無限資金、
跑滿一百二十年、蓋到 385 個分區，人口一樣停在兩萬多不動——**錢與土地都不是
瓶頸，需求被壓成 0 了**。接上之後同一組條件長到十萬人。

遊戲會用訊息提示（「市民要求興建體育館」／「工業需要海港」／「商業需要機場」），
所以**訊息欄不是裝飾，那三則是硬條件**。看到就去蓋，別等有錢再說：
沒解開之前多蓋的分區全部是空的。

價格與佔地：體育場 $3000／4×4，海港 $5000／4×4，機場 $10000／6×6
（DOS 1.10 的數字，見 [`../formats/04-ptf-messages.md`](../formats/04-ptf-messages.md)）。

## 三、電力是跳階的，不是漸進的

**分區必須有電才會發展**，沒電的分區會停止成長，電力久久不恢復就退回空地。
這一點手冊有寫。手冊沒寫的是**供電不足的時候會發生什麼**：

```
一座燃煤電廠供 700 格導電格
一座核能電廠供 2000 格
需要供電的格數超過總容量時 → DoPowerScan 整批放棄
```

出處：`internal/sim/power.go`，見 [`../re/05-power-scan.md`](../re/05-power-scan.md)。

**所以停電不是「大家電力都變弱」，是「一整片同時變暗」。** 容量剛好夠的時候
一切正常，多蓋一格就跳一階。症狀是「城市莫名其妙停止成長」，而畫面上
只有那一片分區沒有閃電記號。

**能用的結論：**

- 導電格**不只是分區**：電線、鋪了電線的路都算在 700 格裡面。
- 電網要留餘裕，不要蓋到剛好。
- 拆東西的時候小心切斷電線——電線被推掉之後，下游一整片會一起變暗，
  而症狀看起來像「城市自然萎縮」。

## 四、稅率：7% 不是黃金比例，是預設值

網路上很常見「7% 是黃金稅率」。查下去發現的是：

**7% 是遊戲自己的預設值。** 新城市 `CityTax: 7`（`sim.c:182`），
載入劇本之後也設成 7（`s_fileio.c:455`）。沒有任何一份一手資料說它最佳。

官方手冊寫的是一個**區間**：`The optimum tax rate for fast growth is between
5 and 7%`（OCR 全文第 1588 行）——7% 是那個區間的**上緣**，不是單一答案。

本專案自動玩家的實測（八個劇本 × 五顆種子）與手冊一致：

| 稅率 | 結果 |
|---|---|
| 4%–9% | 差不多平，看不出明顯高低 |
| **10% 以上** | **急速崩壞**，城市萎縮 |

稅率在程式裡是**平移三條需求曲線**（`z = CityTax + GameLevel`，查 `taxTable[z]`
加到三個閥上），不是乘上比例。同時它也直接進評分：
`ProblemTable[ProbTaxes] = CityTax × 10`，而評分是 `(256 − 問題總和/3) × 4`
——**12% 比 6% 直接少 80 分**。追評分的劇本要記得這件事。

## 五、交通：走不到就搬走

車流用「行程產生」模擬：每個有人口的分區定期產生行程，從分區外圍出發沿路走，
走到「適當的終點」就成功，走不到就失敗。**反覆失敗的分區，居民會搬走。**

真正的終點表比手冊寬（手冊只列了分區，程式用的是連續的圖塊區間）：

| 起點 | 實際可接受的終點 |
|---|---|
| 住宅 | 商業、工業，**外加警局、消防隊、體育場、港口、機場、發電廠** |
| 商業 | 住宅、商業、工業、港口 |
| 工業 | 住宅 |

出處：`s_traf.c:274` 的 `targLow`／`targHigh`，本專案 `internal/sim/traffic.go`。

**能用的結論：**

- **路要貼著分區。** 分區不像導電那樣導車流——分區必須有一格與道路相鄰。
- **車流大會縮短行程範圍**，所以塞車是會自我惡化的：塞→走不到→搬走→
  但同時新的分區又長在別處→更塞。
- **多給幾條替代路線**比拓寬單一幹道有用。

## 六、犯罪、汙染、地價：三者互咬

```
犯罪 = 128 − 地價 + 人口密度  （夾 300）− 警力涵蓋  （夾 0…250）
地價 = (34 − 到市中心的曼哈頓距離) × 4 + 地形 − 汙染 − (犯罪>190 ? 20 : 0)
汙染 = 工業與車流的加權和，再平滑
```

出處：`s_scan.c:200`／`:300`，見 [`../re/06-scans.md`](../re/06-scans.md)。

**能用的結論：**

- **地價為 0 的格子犯罪直接是 0。** 地價只算「有人造物」的格子
  （圖塊編號 ≥ `ROADBASE`），空地不算也不進平均。
- **犯罪的第一項是 `128 − 地價`**，所以**提高地價就是降低犯罪**，
  而且效果是一比一的。長期手段比蓋警局更有效。
- **地價吃「到市中心的距離」**，而市中心是所有分區中心的平均位置——
  它會隨城市長大而移動。攤太開的城市，外圍地價永遠拉不起來。
- **靠近水、樹會加分**（`TerrainMem`）。少推平一點就是省錢又加分。
- 汙染裡**輻射是 255**（其他最高 100），所以核電廠熔毀留下的輻射地是
  長期的地價毒藥。

## 七、一份可以照著做的開局

把上面幾條合起來：

1. **先電廠再分區。** 沒電的分區不長，而且會退回空地。
2. **住宅、商業、工業一起放**，比例接近 1:0.5:0.5（住宅 ≈ 商業＋工業）。
3. **路貼著分區鋪**，不要讓分區離路超過一格。
4. 看到「市民要求興建體育館」就蓋體育場，**不要拖**——同理海港與機場。
   那不是建議，是三堵牆（§二）。
5. **稅率放 5%–7%**，不要碰 10%。
6. 電網留餘裕，接近 700 格（每座燃煤）之前就補下一座。
7. 犯罪高的時候先看地價：地價低才是原因，警局只是止痛。
