## 一、交通不是尋路，是隨機遊走

`MakeTraf`（`s_traf.c:77`）從分區周長找一條路，然後沿路**隨機走最多 30 步**，
每一步看四周有沒有目的地。走到就算通，走不到就算塞。

所以「交通壅塞」在這款遊戲裡是機率現象，不是流量計算——
路網越繞、隨機遊走越難在 30 步內碰到目的地。

三種來源各有自己的目的地範圍（`s_traf.c:274`）：

| 來源 | 目的地 |
|---|---|
| 住宅 | `COMBASE` … `NUCLEAR`（商業與工業）|
| 商業 | `LHTHR` … `PORT` |
| 工業 | `LHTHR` … `COMBASE`（住宅）|

回傳值有三種，呼叫端分開處理：`1` 通、`0` 塞、`-1` 分區邊緣沒有路。
**`-1` 與 `0` 的差別很大**：沒路直接衰退，塞車只是不成長。

### 三個容易寫錯的地方

1. **走進死路時的回溯是「退一格、步數多算三步」**（`s_traf.c:210` 的
   `PosStackN--; z += 3;`）。看起來不對稱，是原版行為。
2. **每走兩步才存一次位置**（`if (z & 1) PushPos()`），所以車流密度只加在
   一半的格子上。
3. `TryGo` 的起始方向用 `Rand16() & 3` 而不是 `Rand(3)`——原始碼註解說
   `Rand(3)` 是**亂數用量最大的地方**，所以改成位元遮罩。兩者分布不同
   （`Rand(3)` 回 0…3，`Rand16()&3` 也是 0…3，但後者不做拒絕取樣），
   而且**消耗的亂數次數不同**。照抄後者。

## 二、分區成長是「需求閥 ＋ 本地評分」的擲骰

```
zscore = 全域需求閥（RValve / CValve / IValve） + 本地評分
沒電的話 zscore 直接設成 −500

成長：zscore > −350  且  (short)(zscore − 26380) > (short)Rand16Signed()
衰退：zscore <  350  且  (short)(zscore + 26380) < (short)Rand16Signed()
```

⚠ **那兩個 26380 是刻意利用 int16 溢位的。** `zscore − 26380` 在 zscore 夠大時
會繞回 int16 的負端，於是「分數越高越容易成長」變成一條非線性曲線。
用 `int` 算會得到完全不同的機率。

⚠ **兩個 if 是並列的，而且 `&&` 短路。** 第一個條件的左半不成立時，
那一次 `Rand16Signed()` **不會被呼叫**。抽樣次數是規則的一部分。

> 本專案第一個被對拍抓到的實作 bug 就在這裡：商業區的第一個條件是
> `TrfGood && (zscore > -350) && (…)`，`TrfGood` 排在最前面。
> 原本寫成「先算完擲骰再檢查 TrfGood」，塞車時會多消耗一個亂數。

三種分區的本地評分（`s_zone.c:569-600`）差很多：

| 分區 | 評分 |
|---|---|
| 住宅 | `(地價 − 汙染)` 夾到 0 以上、左移 5 位、上限 6000，再減 3000。**範圍 −3000…3000** |
| 商業 | 直接讀 `ComRate`（離市中心的距離函數），**範圍 −64…64** |
| 工業 | **永遠 0**（沒路時 −1000）|

所以工業區的成長幾乎完全由全域的 `IValve` 決定，商業區次之，住宅區最看地點。

## 三、四個「照抄才對」的細節

1. **空住宅區（`FREEZ`）每一輪都擲骰**，其餘分區只有八分之一機率
   （`s_zone.c:246` 的 `if ((CChr9 == FREEZ) || (!(Rand16() & 7)))`，`||` 短路）。
2. **`ZonePlop` 的 `base++` 在邊界檢查外面**（`s_zone.c:559`），
   所以貼在地圖邊緣的分區，圖塊編號與地圖中間的不一樣。
3. **`RepairZone` 的計數器同樣在邊界檢查外面**（`s_sim.c:995`）。
4. **`DoResOut` 的三段是獨立的 `if`**（`>16`／`==16`／`<16`），
   `==16` 那段沒有 `return`，會接著掉進 `<16` 的判斷（此時不成立）。

## 四、`MapScan` 的分派順序本身就是規則

```
圖塊 < FLOOD(48)              → 完全跳過（水、樹、空地）
圖塊 < ROADBASE(64)
    ≥ FIREBASE(56)            → 火：四分之一機率蔓延
    < RADTILE(52)             → 水災
    否則                       → 輻射衰變
NewPower 且有 CONDBIT          → 設 PWRBIT
ROADBASE ≤ 圖塊 < POWERBASE    → 道路
有 ZONEBIT                     → 分區
RAILBASE ≤ 圖塊 < RESBASE      → 鐵路
SOMETINYEXP…LASTTINYEXP        → 清成廢墟
```

**火排在分區前面**，所以燒起來的分區走的是火的路徑，不會同時成長。
