# 10 — 城市評分與市民投票

**推論等級：已確認（讀出來的部分）／未驗收（整刻對拍尚未對齊）**。
日期 2026-08-29。接線：`internal/sim/eval.go`。

## 一、七個問題

`DoProblems`（`s_eval.c:163`）填一張問題表，數值越大越嚴重：

| 索引 | 問題 | 來源 |
|---|---|---|
| 0 | 犯罪 | `CrimeAverage` |
| 1 | 汙染 | `PolluteAverage` |
| 2 | 住房 | `LVAverage × 0.7` |
| 3 | 稅賦 | `CityTax × 10` |
| 4 | 交通 | `AverageTrf()` |
| 5 | 失業 | `GetUnemployment()` |
| 6 | 火災 | `FirePop × 5`，上限 255 |

**住房問題用的是地價**——地價越高，住房問題越嚴重。

## 二、投票

`VoteProblems`（`s_eval.c:201`）讓市民對問題投票：

```c
while ((z < 100) && (count < 600)) {
  if (Rand(300) < ProblemTable[x]) { ProblemVotes[x]++; z++; }
  x++;
  if (x > PROBNUM) x = 0;
  count++;
}
```

⚠ **索引遞增到 `> PROBNUM`（10）才歸零，但問題只有 0…6 有值。**
所以 7、8、9、10 這四輪一定不會投票，而且 `ProblemTable[10]` 會
**越界讀取**（陣列長度就是 10）。Go 版把索引夾在陣列內；
這是與原版的行為差異，但越界讀到的是相鄰變數的位元組，
原版自己也不保證那個值——**這裡刻意不重現未定義行為**。

投票也是整個模擬**最大的亂數消耗者**：最多 600 次 `Rand(300)`
加 100 次 `Rand(1000)`，一次評分約 650 個亂數
（見 [`12-tick-parity.md`](12-tick-parity.md) §5）。

## 三、分數

`GetScore`（`s_eval.c:276`）：

```
x = 七個問題的總和 / 3，上限 256
z = (256 − x) × 4，夾到 0…1000

三種上限（體育場／海港／機場沒蓋）各乘 0.85
道路效果不足        減 (32 − RoadEffect)
警察效果不足        乘 (0.9 + PoliceEffect/10000.1)
消防效果不足        乘 (0.9 + FireEffect/10000.1)
三個需求閥 < −1000  各乘 0.85
人口成長率乘數
減去火災分數
減去稅率
乘上「有電分區的比例」

CityScore = (舊分數 + z) / 2
```

⚠ **最後一行是一階平滑**——新分數只佔一半，所以分數不會跳。
初始分數是 **500**，不是 0：空城不會掉到谷底。

⚠ `10000.1` 這個除數不是筆誤，是為了讓 `PoliceEffect = 1000` 時
乘數略小於 1.0（0.99999）。照抄。

## 四、城市等級

`DoPopNum`（`s_eval.c:142`）：

```
城市人口 = (住宅人口 + 商業人口×8 + 工業人口×8) × 20
```

| 門檻 | 等級 |
|---:|---|
| — | 村莊 |
| > 2000 | 小鎮 |
| > 10000 | 城市 |
| > 50000 | 首府 |
| > 100000 | 大都會 |
| > 500000 | 巨型都會 |

**「城市人口」與住宅人口不是同一件事**：商業與工業各乘 8，再整體乘 20。
劇本的通關門檻（軟體世界說明書譯為「明日之都」）用的是這個數字。
