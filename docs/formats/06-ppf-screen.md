# `.PPF` — 整幅畫面（開場與劇本選單）

**推論等級：六種版面都已確認**。日期 2026-08-30，2026-09-02 補三種。
工具：[`tools/ppfdump`](../../tools/ppfdump/main.go)、
[`tools/pgfpal`](../../tools/pgfpal/main.go)；解碼在
[`internal/assets/ppf.go`](../../internal/assets/ppf.go)。

`.PPF` 存的是一整幅畫面，不是圖塊。DOS 1.10 只有兩幅：

| 檔名樣式 | 內容 |
|---|---|
| `<模式>NTRO.PPF` | 標題畫面，三個按鈕：`START NEW CITY`／`LOAD A CITY`／`SELECT SCENARIO` |
| `<模式>SCEN.PPF` | 劇本選單，八格縮圖 ＋ 城市名／國家／年份／災難類別 |

外層是與 `.PGF`／`.PSN`／`.PTF`／`.PSF` 同一套的 LZSS（[`02-dos-lzss.md`](02-dos-lzss.md)），
解壓後**沒有檔頭**，第一個位元組就是畫面資料。

## 一、版面：逐列交錯的位元平面

解壓後的長度剛好等於 `寬 × 高 ÷ 8 × 平面數`：

| 模式 | 寬 | 每列位元組 | 像素排法 | 實測到的高度 |
|---|---:|---:|---|---|
| `cega` | 640 | 320 | 四個位元平面 | 350 |
| `sega` | 320 | 160 | 四個位元平面 | 200 |
| `tdy` | 320 | 160 | 四個位元平面 | 200（與 `sega` 同一個版面）|
| `mcga` | 320 | 320 | 每像素一位元組（256 色）| 199、200 |
| `mono` | 640 | 80 | 一個位元平面 | 336、347、348 |
| `cga` | 320 | 80 | **封裝式 2bpp**（一位元組四像素）| 175、200 |

高度**不記在表裡**，由檔案長度除以每列位元組數得到。二十二個檔案的實測：

| 檔案 | 來源 | 解壓 | 解出 |
|---|---|---:|---|
| `CEGANTRO.PPF`／`CEGASCEN.PPF` | 1.03／1.10 | 112000 | 640×350 |
| `SEGANTRO.PPF`／`SEGASCEN.PPF` | 1.03／1.10 | 32000 | 320×200 |
| `TDYNTRO.PPF`／`TDYSCEN.PPF` | 1.03 | 32000 | 320×200 |
| `MONONTRO.PPF` | 1.03 | 26880 | 640×336 |
| `MONOSCEN.PPF` | 1.03 | 27840 | 640×348 |
| `CGANTRO.PPF` | 1.03 | 14000 | 320×175 |
| `CGASCEN.PPF` | 1.03 | 16000 | 320×200 |
| `mcgantro.ppf` | 1.10 | 63680 | 320×199 |
| `mcgascen.ppf` | 1.10 | 64000 | 320×200 |
| `*TE.PPF`（地形編輯器）| 軟體世界 1990 | 見上 | 六種模式各一 |

⚠ **高度不是每個模式一個常數。** 同一個模式的招牌與劇本選單可以不一樣高：
CGA 是 175 對 200、MONO 是 336 對 348、MCGA 是 199 對 200。把高度寫死成常數，
同一個模式裡會有些畫面讀得出來、有些整幅讀不出來——而在別的模式下玩完全
看不出問題。2026-09-02 之前就是這樣讓「MCGA 的劇本選單讀不出來」活下來的。

⚠ **`mono` 與 `cga` 的每列位元組數都是 80，光看長度分不出是哪一種。**
16000 可以是 CGA 320×200，也可以是 MONO 640×200。這兩種必須由呼叫端指定模式
（`ParsePPFAs`）；遊戲自己也是靠 `SIMCITY.CFG` 知道要載哪一組檔案的。
`ParsePPF` 只認長度無歧義的 `cega`／`sega`／`mcga`。

⚠ **高度範圍是消歧義的必要條件。** 32000 除以 CEGA 的每列 320 剛好是 100，
少了「CEGA 高度應在 300–400」這個限制，sega 的畫面會被當成 CEGA 的 640×100
解出來——畫面出得來、長度檢查也過，只是整幅是錯的。

⚠ **CGA 不是位元平面。** 320×200 的封裝式 2bpp 與「兩個位元平面」都剛好用掉
16000 位元組，長度檢查兩種都會過；位元平面畫出來是剪切狀的條紋，封裝式畫出來
是乾淨的招牌與按鈕。裁決方式是兩種都畫出來看。
CGA 真正的四色盤還沒從資料裡讀出來，目前沿用 EGA 前四色當佔位（**未解**）。

六種模式的完整樣本來自 **DOS 1.03**（玩家自備，不入版控）：它是目前唯一
六種顯示模式的 `.PPF` 與 `.PGF` 都齊全的一份。1.10 那份只有 `CEGA`／`sega`／
`mcga`。Tandy 的版面另有軟體世界 1990 年地形編輯器磁片的一份獨立佐證
（[`00-e220-terrain-editor.md`](00-e220-terrain-editor.md)）。

**平面是逐列交錯的，不是一整面接一整面**，而且**高位在前**：

```
列 y 的第 p 個平面、第 b 個位元組  →  (y*4 + p) * (寬/8) + b
像素 (b*8+bit) 的色號 = Σ 平面 p 的第 (7−bit) 位 << (3−p)
```

也就是第一個平面是 EGA 的 I（亮度），最後一個才是 B。

兩件事都會產生「看起來很合理但錯」的畫面，而且兩種錯的長度檢查都會過：

| 弄錯的地方 | 症狀 |
|---|---|
| 一整面接一整面 | 橫條錯位的雜訊，勉強看得出字形 |
| 平面順序反過來（B 在前）| **版面完全正確、顏色整組錯位**——招牌變成紅色的 |

第二種特別危險：畫面漂亮、字讀得出來、按鈕框線位置分毫不差，
只有顏色不對。抓到它的是與 DOSBox 實跑逐像素對拍。

調色盤是**標準 EGA 十六色**（`00`/`55`/`AA`/`FF` 四階那組），檔案本身不帶調色盤。
順序修正之後，招牌與劇本選單兩幅畫面與 DOS 1.10 實跑**逐像素相同**，
224000 個像素只差滑鼠游標那個 16×15 的方塊
（2026-08-30，`tools/dosbox/act-ppf.txt` ＋ `tools/ppfdump`）。

## 二、另外兩種顯示模式（已用 DOSBox 逐模式對拍）

`SIMCITY.CFG` 的 `Screen Mode` 換成 `e`（Lores EGA Color）與 `2`
（256 Color VGA/MCGA）各跑一次，拿開機那一幕對拍
（`tools/dosbox/act-ppf2.txt`，`CFG_SCREEN` ＋ `CFG_GFX`）：

- **`sega` ＝ 320 × 200 × 4 平面。** 長度 32000 同時相容
  `640×200×4` 與 `320×400×4`，光看長度挑不出來；實跑的畫面是 320×200
  （DOSBox 放大成 640×400）。逐像素對拍**只差滑鼠游標那 128 個點**。
- **`mcga` ＝ 320 × 199，每像素一個位元組。** 199 不是 200——
  最上面那一列對齊螢幕第 0 列（位移 1 的假設會讓調色盤反查整個散掉：
  37 個色號只剩 1 個對應唯一顏色，位移 0 則有 30 個）。
- **`mcga` 的調色盤取自同一個圖形集的 `.PGF`。** 把螢幕上的顏色照色號
  反查回來，37 個用到的色號與 `westmcga.pgf` 的調色盤**全部相符**，
  最大差 3——那是六位元 VGA 值展成八位元的兩種算法差異
  （檔案存 `(v<<2)|3` ＝ 171，DOSBox 輸出 `v×255÷63` ＝ 170）。

⚠ 少的那一列（第 199 列）畫的是什麼**還沒解**：實跑的畫面第 199 列是黑的，
但那也可能是遊戲自己清掉的。這一項列進待補清單。
