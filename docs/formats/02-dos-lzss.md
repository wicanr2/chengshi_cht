# 02 — DOS 版的共用壓縮與四種資料檔

**推論等級：已確認**（實測反推參數，並用四種互相獨立的結構性證據交叉驗證）。
日期 2026-08-29。接線：`internal/assets/lzss.go`、`ptf.go`、`psn.go`。

## 一、一種壓縮打開全部四種資料檔

DOS 1.10 的 `.PGF`（圖形）、`.PPF`（整幅畫面）、`.PSN`（劇本）、`.PSF`（音效）
**用的是同一套 LZSS**。`SOUNDDAT.V4` 是同一份音效資料的**未壓縮版本**。

| 檔案 | 壓縮 | 解壓 | 比例 |
|---|---:|---:|---:|
| `CEGA/CEGADAT.PGF` | 90292 | 219552 | 41% |
| `CEGA/CEGANTRO.PPF` | 22799 | **112000** | 20% |
| `SCENARIO/DULLSVIL.PSN` | 6281 | **27264** | 23% |
| `DATA/SOUNDDAT.PSF` | 17951 | **26002** | 69% |
| `DATA/MESSAGE.PTF` | 4885 | 8288 | 59% |
| `SOUNDDAT.V4` | — | 26002（未壓縮）| — |

## 二、參數

```
環形緩衝    4096 位元組，初值全部填 0x20（空白）
寫入指標    起點 4078 ＝ 4096 − 18
旗標        一個位元組帶八個項目，LSB 先；1 ＝ 字面量，0 ＝ 回指
回指        兩個位元組：off = b1 | ((b2 & 0xF0) << 4)
                        len = (b2 & 0x0F) + 3
```

這是教科書上的 LZSS（Okumura/Yoshizaki 那一版），**唯一要小心的是寫入指標的起點**：
`4096 − 18`，不是 `4096 − 16` 也不是 `4096 − 20`。差一格就會得到

```
More residential zones needed.\0\xfe\x02More rcommercal zones needed.
```

——**前半段完全正確，後半段錯得很像對的**。這是本專案目前最典型的「自洽但錯」樣本：
只看第一句會以為解對了。

參數是**實測反推**的，`SIMCITY.EXE` 還沒反組譯。所以驗證靠的是四個互相獨立的
結構性巧合，任何一個對不上都代表參數錯：

| 證據 | 為什麼獨立 |
|---|---|
| `.PPF` 解出來剛好 **112000** ＝ 640 × 350 ÷ 8 × 4 | EGA 高解析四個位元平面的精確大小 |
| `.PSN` 解出來剛好 **27264** ＝ 144 ＋ **27120** | 27120 是 Micropolis `.cty` 的大小 |
| `DATA/SOUNDDAT.PSF` 解出來 **26002** ＝ `SOUNDDAT.V4` 的檔案大小 | 同一份資料的壓縮版與未壓縮版 |
| 七個 `.PTF` 解出來 **97–98% 是可列印字元** | 參數錯一點點，長度還在、比例會掉 |

> 順帶一提：`.PPF` 的 112000 同時證實了 **`CEGA` 是 640×350**
> （官方手冊寫「EGA High-Res Color」，這裡拿到了位元組級的佐證）。

## 三、`.PTF` 訊息檔

解壓後的版面：

```
0..2    三個位元組的檔頭（前兩個是小端 16 位元，各檔不同；第三個固定 0x32）
3       NUL
4..     記錄串：<NUL 結尾的字串> <NUL 結尾的標記>
```

標記的第一個位元組固定是 `0xFE`，第二個位元組在 `0x02`…`0x09` 之間變動，
看起來是訊息的嚴重程度或對應的音效編號——**未解，原樣保留**。

七個訊息檔：`MESSAGE.PTF`（基本）＋ 六個圖形集各一份
（`ASIA`／`FEUR`／`FUSA`／`MEDI`／`MOON`／`WEST`）。
每份 46 條短訊息 ＋ 工具價目 ＋ 數則長篇報紙文字。

**中文化以序號為鍵，不以原文為鍵**（`internal/assets/ptf.go` 的 `Message.Index`）。
理由有二：原文屬於原權利人，不該進本專案的版控；而且六個圖形集的同一個序號
講的是同一件事、用詞不同，用序號才對得起來。

## 四、`.PSN` 劇本檔 —— DOS 版與 Micropolis 是同一個城市格式

解壓後 27264 位元組：

```
0..1      大端 16 位元的城市名長度
2..       城市名（"Dullsville"、"Bern"、"Rio2"、"SanFran"…）
…         零填到 64 附近
~65..72   魔數 "CITYMCRP"
…         其餘檔頭欄位未解
144..     27120 位元組的城市資料
```

那 27120 位元組**與 Micropolis 的 `.cty` 是同一個版面**：大端 16 位元、
七個陣列的順序相同、地圖 120×100 且 x 外層 y 內層。
已驗證八個劇本全部能被 `sim.ParseCityFile` 直接解析，
而且每一格的圖塊編號都 < `TILE_COUNT`。

> **這收掉了 `docs/formats/01-city-file.md` §5 的一個未解項目**：
> 「DOS 版的 `.PSN` 是不是同一個格式」——是。
> 也收掉了 `docs/re/03-map-and-tiles.md` §4 的
> 「DOS 版是不是同一套圖塊編號與同一個 120×100」——是。
>
> 當初判斷「大小不同（6–11 KB vs 27120），八成有壓縮」是對的方向，
> 但「所以是另一個格式」的推論是錯的。**壓縮不是格式差異。**

DOS 的城市名與 Micropolis 的不完全一樣：`Rio2`、`SanFran` 是檔名式寫法，
不是顯示用的名稱。顯示名在別處（執行檔或劇本選單畫面），未解。

## 五、`.PSF` / `.V4` 音效

`DATA/SOUNDDAT.PSF` 解壓後與 `SOUNDDAT.V4` **長度相同（26002）**，
所以 `.PSF` 就是壓縮過的 `.V4`（現在有測試守著逐位元組相同）。
內部格式見 [`05-psf-sound.md`](05-psf-sound.md)。

根目錄另有一份 2012 年時間戳的 `SOUNDDAT.PSF`，與 `DATA/` 那份內容不同
（見 `00-dos110-inventory.md` §1）。哪一份被遊戲讀還沒查。
