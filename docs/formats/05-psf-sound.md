# 05 — `.PSF` / `.V4` 音效檔

`DATA/*_SND.PSF`（六個風格）、`DATA/SOUNDDAT.PSF`（基本）與根目錄的
`SOUNDDAT.PSF`（2012 年那份）都是同一個格式，`SOUNDDAT.V4` 是它的未壓縮版。

實作在 [`internal/assets/psf.go`](../../internal/assets/psf.go)，
機器檢查在 `psf_test.go`。

## 一、外層是四種資料檔共用的 LZSS

與 `.PGF`／`.PPF`／`.PSN`／`.PTF` 同一套（[`02-dos-lzss.md`](02-dos-lzss.md)），
而且沒有橫幅、沒有前置檔頭，第一個位元組就是壓縮流。

`DATA/SOUNDDAT.PSF` 解出來與 `SOUNDDAT.V4` **逐位元組相同**，所以
「`.PSF` 就是壓縮過的 `.V4`」不是推論，是量出來的。

## 二、版面：長度鏈

```
u16  之後的位元組數（＝檔案大小 − 2）
重複：
    u16  這一段的位元組數
    位元組 × 該長度
```

九份檔案跑下來都是**剛好八段**，而且最後一段的結尾正好落在檔尾。

段數不必另外找一張表——**鏈自己把它釘死了**。長度只要錯一個位元組，
走到後面就會停在檔案中間或超出去；九份檔案同時走到底，是很強的證據。

| 檔案 | 八段的位元組數 |
|---|---|
| `DATA/SOUNDDAT.PSF`（＝`SOUNDDAT.V4`）| 5632 4352 5376 6720 2560 192 384 768 |
| `DATA/ASIA_SND.PSF` | 5257 4352 3750 5172 1770 463 384 768 |
| `DATA/MEDI_SND.PSF` | 5835 4352 2048 5172 1770 463 384 768 |
| `DATA/WEST_SND.PSF` | 5763 4352 3720 5172 1770 463 384 768 |
| `DATA/FEUR_SND.PSF` | 2666 4352 3992 6180 2560 405 384 768 |
| `DATA/FUSA_SND.PSF` | 2666 4352 2933 6488 2560 405 384 768 |
| `DATA/MOON_SND.PSF` | 2666 4352 2856 6720 3592 768 384 768 |
| 根目錄 `SOUNDDAT.PSF`（2012）| 5632 4352 3750 6720 2560 192 384 768 |

### 段長的對齊：基本檔補齊到 64，風格檔沒有

**推論等級：已確認**（量出來的，2026-08-30）。

| 檔案 | 八段是不是 64 的倍數 |
|---|---|
| `SOUNDDAT.V4`（＝`DATA/SOUNDDAT.PSF`）| ✓✓✓✓✓✓✓✓ **全部是** |
| `ASIA`／`WEST`／`FEUR` | ✗✓✗✗✗✗✓✓ |
| `MEDI` | ✗✓✓✗✗✗✓✓ |

三個共用段（1、6、7 —— 每份檔案數值都一樣：4352／384／768）本來就對齊。
其餘的：**基本檔補齊、風格檔沒補**。

這件事有實際後果：**基本檔的段長不是錄音的實際長度**，所以拿長度去對
X11 版那 46 個具名 `.au` 檔是行不通的（見 [`../re/16-dos-oracle.md`](../re/16-dos-oracle.md) §4.3）。

## 三、樣本是 4 位元 PCM，高位 nibble 在前

一個位元組兩個取樣，值域 0–15，中心是 8——所以靜音在十六進位裡就是
一整片 `88 88 88`，肉眼就看得出來。

**nibble 順序是量出來的，不是猜的**：把兩種順序都攤開，比相鄰取樣的
平均絕對差（拆錯會把波形打散、差值變大）。九個檔案、七十二段，
每一段都是高位在前比較平滑，差距 1.5–2 倍，沒有例外。

## 四、哪幾段跟著風格換

以段為單位算雜湊，可以看出哪些是「世界的聲音」哪些不是：

| 段 | 跟著換嗎 |
|---|---|
| 0 | 三個古代風格各有一份；三個未來風格共用一份；基本檔另一份 |
| 1 | **九份檔案完全相同** |
| 2 | 每一個風格都不一樣 |
| 3、4、5 | 依「年代」分組：古代三個一組、未來兩到三個一組 |
| 6 | **九份檔案完全相同** |
| 7 | 基本檔一份，六個風格共用另一份 |

根目錄那份 2012 的 `SOUNDDAT.PSF` 只有第 2 段與 `DATA/` 那份不同，
其餘七段一模一樣。

## 五、八段各是什麼

**推論等級：已確認**（反組譯 `PlaySound(n)` 的十一個呼叫點，
逐支比對所在函式與 Micropolis 的對應函式）。證據與逐項對照寫在
[`../re/16-dos-oracle.md`](../re/16-dos-oracle.md) §五之四。

| 段 | 事件 | 長度上的旁證 |
|---:|---|---|
| 0 | 交通壅塞（直升機回報）| 隨風格換——古代三份、未來共用一份 |
| 1 | 爆炸 | **九份檔案完全相同**：爆炸不隨世界風格改變 |
| 2 | 怪獸吼叫 | 每個風格都不一樣：不同年代不同怪物 |
| 3 | 警笛 | 依年代分組 |
| 4 | 船笛 | 依年代分組 |
| 5 | 工具成功（工具編號 ≤ 4）| 192–768 位元組 ＝ 0.04–0.14 秒，UI 音的長度 |
| 6 | 工具成功（工具編號 > 4）| **九份完全相同**且固定 384 位元組 |
| 7 | 工具失敗 | 基本檔一份、六個風格共用另一份 |

§四那張「哪幾段跟著風格換」的表原本只是觀察，現在它與事件對應**互相印證**：
唯二九份完全相同的是**爆炸**與**其中一個工具音**——正好是兩個與世界風格無關的聲音。

## 六、取樣率：約 5.3–5.45 kHz

**推論等級：強證據**（三段獨立的長度比，不是從程式碼直讀）。
量法與不確定度寫在 [`../re/16-dos-oracle.md`](../re/16-dos-oracle.md) §五之五。

段 0、1、4 對上 X11 版同名 `.au`（8000 Hz）的取樣數比值分別是
0.678／0.677／0.673，彼此差 0.8% 以內 → **5400 Hz 上下**。
基本檔段長補齊到 64 的倍數，最多多算 126 個取樣，所以區間是 5300–5450 Hz。

取樣率的常數在音效卡驅動的**初始化**那一段（DMA 驅動的卡，
`sub_DD83` 送命令）。下一個入口是符號表裡的 `_InitSounds`。

## 七、未解

- **取樣率的精確值**（見 §六：有區間，沒有從程式碼直讀的常數）。
- 播放硬體（Tandy 音效 BIOS `INT 1Ah AH=83h`／Covox Sound Master）
  各自怎麼餵這些樣本。
- **沒辦法用耳朵驗收**：`T` 走 Tandy 音效 BIOS，DOSBox-X 沒實作；
  `S` 的 Sound Master 沒有模擬器。內建喇叭放的是程式自己合成的嗶聲，
  不是這八段 PCM（判準：換掉音效檔再錄一次，聲音逐取樣相同）。
  詳見 [`../re/16-dos-oracle.md`](../re/16-dos-oracle.md) §4。
