# 05 — `.PSF` / `.V4` 音效檔

`DATA/*_SND.PSF`（六個風格）、`DATA/SOUNDDAT.PSF`（基本）與根目錄的
`SOUNDDAT.PSF`（2012 年那份）都是同一個格式，`SOUNDDAT.V4` 是它的未壓縮版。

實作在 [`internal/assets/psf.go`](../../internal/assets/psf.go)，
機器檢查在 `psf_test.go`。

## 一、外層是四種資料檔共用的 LZSS

與 `.PGF`／`.PPF`／`.PSN`／`.PTF` 同一套（[`02-dos-lzss.md`](02-dos-lzss.md)），
而且沒有橫幅、沒有前置檔頭，第一個位元組就是壓縮流。

`DATA/SOUNDDAT.PSF` 解出來與 `SOUNDDAT.V4` **逐位元組相同**，所以
「`.PSF` 就是壓縮過的 `.V4`」不是推論，是量出來的。

## 二、版面：長度鏈

```
u16  之後的位元組數（＝檔案大小 − 2）
重複：
    u16  這一段的位元組數
    位元組 × 該長度
```

九份檔案跑下來都是**剛好八段**，而且最後一段的結尾正好落在檔尾。

段數不必另外找一張表——**鏈自己把它釘死了**。長度只要錯一個位元組，
走到後面就會停在檔案中間或超出去；九份檔案同時走到底，是很強的證據。

| 檔案 | 八段的位元組數 |
|---|---|
| `DATA/SOUNDDAT.PSF`（＝`SOUNDDAT.V4`）| 5632 4352 5376 6720 2560 192 384 768 |
| `DATA/ASIA_SND.PSF` | 5257 4352 3750 5172 1770 463 384 768 |
| `DATA/MEDI_SND.PSF` | 5835 4352 2048 5172 1770 463 384 768 |
| `DATA/WEST_SND.PSF` | 5763 4352 3720 5172 1770 463 384 768 |
| `DATA/FEUR_SND.PSF` | 2666 4352 3992 6180 2560 405 384 768 |
| `DATA/FUSA_SND.PSF` | 2666 4352 2933 6488 2560 405 384 768 |

| 根目錄 `SOUNDDAT.PSF`（2012）| 5632 4352 3750 6720 2560 192 384 768 |

## 三、樣本是 4 位元 PCM，高位 nibble 在前

一個位元組兩個取樣，值域 0–15，中心是 8——所以靜音在十六進位裡就是
一整片 `88 88 88`，肉眼就看得出來。

**nibble 順序是量出來的，不是猜的**：把兩種順序都攤開，比相鄰取樣的
平均絕對差（拆錯會把波形打散、差值變大）。九個檔案、七十二段，
每一段都是高位在前比較平滑，差距 1.5–2 倍，沒有例外。

## 四、哪幾段跟著風格換

以段為單位算雜湊，可以看出哪些是「世界的聲音」哪些不是：

| 段 | 跟著換嗎 |
|---|---|
| 0 | 三個古代風格各有一份；三個未來風格共用一份；基本檔另一份 |
| 1 | **九份檔案完全相同** |
| 2 | 每一個風格都不一樣 |
| 3、4、5 | 依「年代」分組：古代三個一組、未來兩到三個一組 |
| 6 | **九份檔案完全相同** |
| 7 | 基本檔一份，六個風格共用另一份 |

根目錄那份 2012 的 `SOUNDDAT.PSF` 只有第 2 段與 `DATA/` 那份不同，
其餘七段一模一樣。

## 五、未解

- **每一段對應哪一個事件**。這是接上遊戲之前必須先解決的。
  試過拿 X11 版有名字的音效（`micropolis-activity/res/sounds/`）比對包絡線，
  相關係數落在 0.6–0.9 之間且彼此矛盾（第 7 段是一段乾淨的正弦音，卻比到
  「粉筆聲」），**判不出來**，不採用。
  DOSBox 實跑做到一半（[`../re/16-dos-oracle.md`](../re/16-dos-oracle.md) §4）：
  DOSBox-X 的 `pcspeaker=impulse` 錄得到**四種可重現的長度**
  （0.030 推土、0.115 建造／訊息、0.279 查詢／失敗、1.90 災難整頁訊息），
  但只有 0.115 秒那個對得到第 5 段（相關 0.90–0.95，取樣率要假設 8000 上下），
  其餘三個對不上，長度也湊不出一致的取樣率。差異是系統性偏短，形狀像
  DOSBox 把尾巴截掉。
  剩下的路：找一份帶 `tdy\` 圖形檔的副本走 Tandy DAC（`Sound: S` 是
  **Covox Sound Master** 音效卡，沒有模擬器支援，遊戲自己會回報找不到），
  或反組譯 `SIMCITY.EXE` 的發聲程式。
- **取樣率**。檔案裡沒寫，`simtool sound` 預設的 8000 只是佔位值。
  同一次 DOSBox 實跑可以一併定案：錄到的長度除以段的取樣數就是取樣率。
- 播放硬體（PC 喇叭 PWM／Tandy DAC／Sound Blaster）各自怎麼餵這些樣本。

在這兩項定案之前，**音效不接進遊戲**——播錯聲音等於把一條沒有證據的
斷言寫進產品。
