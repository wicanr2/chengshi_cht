# 04 — `.PTF` 訊息檔

**推論等級：已確認**（版面與內容都以七個原版檔驗證）。日期 2026-08-29。
接線：`internal/assets/ptf.go`、`internal/i18n/i18n.go`。

## 一、版面

用的是四種資料檔共用的 LZSS（[`02-dos-lzss.md`](02-dos-lzss.md)）。
解開之後是一串**段落**，一段一個用途：

```
u16  段落長度（不含這四個位元組）
u16  筆數
     連續的 NUL 結尾字串
```

七個檔（基本 ＋ 六個風格包）都是 **22 段、235 筆文字**。

## 二、「筆數」不等於字串數

第 0 段（狀態訊息）**一筆是兩個字串**：文字，加上兩個位元組的屬性
（`0xFE` 開頭，第二個位元組疑似音效或嚴重度）。其餘段落一筆一個字串。

這個差別會產生一個非常難發現的錯誤。把整份檔案當成「文字、屬性」交替
去讀——那對第 0 段是對的——月份會變成

```
一月、三月、五月、七月、九月、十一月
```

**二月被當成一月的屬性吃掉了。** 輸出看起來完全合理，長度也對，只是
少了一半。而「解出幾筆」「可列印比例」這類結構性檢查全都通過。

現在月份是回歸哨兵：`internal/assets/assets_test.go` 明確比對十二個月。

> 教訓寫成規則：**當一個格式的記錄形狀隨段落而變，不要用全域的
> 交替假設去讀。** 交替假設在第一段成立時最危險——它會讓你相信
> 整份檔案都解對了。

## 四、原版資料檔證實了說明書的造價

第 1 段自己寫著：

```
Stadium: $3000
Seaport: $5000
Nuclear reactor: $5000
Coal power plant: $3000
Airport: $10000
```

軟體世界說明書寫的也是體育館 $3000、海港 $5000，而 Micropolis 的
`w_tool.c` `CostOf[]` 是體育館 5000、海港 3000——**剛好對調**。

所以：**說明書沒錯，Micropolis 才是改過的那一份。** 這條原本記在
`CONTEXT.md` 的未解清單，現在結案。呈現層顯示的造價一律取自訊息檔。

> 這也是「一手資料勝過二手推論」的一個實例：兩份一手資料（DOS 資料檔、
> 當年的說明書）一致，而它們與另一份一手資料（Unix 版原始碼）不一致時，
> 要判斷的是「哪一份對應到我要重現的那個版本」，不是「哪一份比較可信」。

## 五、風格包換掉的不只是外觀

六個風格包各自改寫了 70–94 筆文字，包含**口吻**：

| 風格 | 「住宅區不足」變成 | 發電廠 | 鐵路 | 體育館 |
|---|---|---|---|---|
| 古代亞洲 | 主上，我們需要更多住宅區 | 水井 | 人力車道 | 相撲場 |
| 中世紀 | 陛下，我們需要更多住宅區 | 水井 | 馬車道 | 比武場 |
| 西部拓荒 | 咱們得多蓋幾間屋子 | 水車 | 蒸汽火車軌道 | 牛仔競技場 |
| 未來美國 | 我們要求更多住宅區 | 核分裂發電廠 | 磁浮軌道 | 雷射機器人球場 |
| 未來歐洲 | Mehr 住宅區，bitte | 核分裂發電廠 | 單軌 | 立體足球場 |
| 月球殖民地 | 需要更多住宅巨蛋 | 核能發電廠 | 軌道 | 低重力休閒中心 |

未來歐洲那一組刻意混用德文與法文（`Mehr … bitte`／`Plus … s'il vous
plait`），**語言本身就是笑點**，所以譯文保留那兩個外語詞。

災難也跟著換：古代亞洲的龍捲風是「颱風」、水災是「海嘯」、輻射是「瘟疫」、
空難是「龍息爆襲」。月球殖民地的地震是「月震」、水災是「黴菌蔓延」。

## 六、DOS 版有五段速度，Micropolis 只有四段

第 19 段列出 `Fastest 4 / Fast 3 / Average 2 / Slow 1 / Pause 0`，
而 Micropolis 的 `SimSpeed` 只有 0–3。

呈現層的對照表因此不是 `4 − n`：`SimSpeed 3`（最快）要對到第 0 筆，
不是第 1 筆。用減法算會讓玩家在最高速時看到「快速」——數字看起來合理，
但名稱是錯的。

## 七、圖片訊息自己帶著事件編號

第 2 段裝的是「停下遊戲、跳出一整頁」的圖片訊息（交通警告、核災、
劇本簡介、人口里程碑…）。它們的**排列順序和事件編號無關**：檔案裡
第 0 筆是交通警告，第 12 筆是底特律劇本，中間夾著人口里程碑。

對應關係寫在字串自己身上。每一筆的前三個位元組是 `FE` 加一個
little-endian int16，而那個數字是**前一筆**的事件編號取負值：

```
2.0   FE F4 FF  → -12   交通警告      （Micropolis 的 SendMesAt(-12)）
2.2   FE D5 FF  → -43   核子熔毀
2.3   FE 9C FF  → -100  過關
2.4   FE 38 FF  → -200  彈劾
2.15  FE FD FF  → -3    漢堡劇本
```

負號是原版區分兩種訊息的方式：`SendMes(n)` 的 `n > 0` 走跑馬燈，
`n < 0` 走圖片視窗（`s_msg.c` 的 `SendMes`／`DoAutoGoto`）。所以
呈現層只要拿 `-n` 去查這張表就好，不必再維護一份事件到圖片的對照。

實作上要注意兩件事：

- **前三個位元組固定要剝掉，不能「剝到第一個可列印字元為止」。**
  彈劾的編號 −200 是 `0x38 0xFF`，而 `0x38` 就是 ASCII 的 `8`；
  用可列印性當終止條件會讓怪獸攻擊那一筆顯示成 `8?MONSTER ATTACK`。
- 第 2 段最後兩筆的編號是 0，內容是空的，不是訊息（見上面 2.20／2.21）。

八個劇本簡介會**隨風格改寫**，但劇本的城市名來自 `.PSN` 檔頭
（`Hamburg`），不隨風格變。所以中世紀風格下玩劇本 3，狀態列寫
「漢堡　1944」而簡介寫「史邦美樂，1535」——原版就是這個組合。
